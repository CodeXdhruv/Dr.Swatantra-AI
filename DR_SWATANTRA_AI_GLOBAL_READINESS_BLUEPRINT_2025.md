## 3. System Architecture Overview

### Technology Stack:

**Frontend Framework:**
- **Primary:** Flutter SDK 3.8.0+ (Dart language)
- **UI Library:** Material Design 3 with custom components
- **Responsive Design:** flutter_screenutil (392x844 base design)
- **State Management:** Provider pattern for theme and navigation
- **Animation:** Flutter Animation API with custom transitions

**Backend Framework:**
- **Authentication:** Firebase Authentication (Email, Google OAuth, Anonymous)
- **Database:** Cloud Firestore (NoSQL, real-time sync)
- **Storage:** Firebase Cloud Storage (profile photos, content assets)
- **Analytics:** Firebase Analytics + Crashlytics
- **Voice Processing:** Python Flask server with PyAudio integration

**Database:**
- **Primary:** Cloud Firestore (user profiles, preferences, session data)
- **Local:** SharedPreferences (user settings, theme preferences)
- **Knowledge Base:** In-memory RAG system (360 pre-computed embeddings)
- **Caching:** cached_network_image for content optimization

**Cloud Infrastructure:**
- **Platform:** Google Cloud Platform (Firebase ecosystem)
- **Regions:** us-central1 (primary), multi-region expansion planned
- **CDN:** Firebase Hosting for static content delivery
- **Monitoring:** Firebase Performance Monitoring + Custom Logger

**API Services:**
- **Primary AI:** Google Gemini 2.0 Flash (text generation)
- **Embeddings:** Google Generative AI Embedding Model
- **Voice AI:** Gemini Live API (real-time voice conversations)
- **Additional:** YouTube Data API (content integration)

### Data Flow Diagram:
```
[Mobile App] ↔ [Firebase Auth] ↔ [User Authentication]
     ↓
[Chat Interface] → [Gemini Service] → [Google Gemini API]
     ↓                    ↓
[RAG System] ← [Embedding Model] ← [Knowledge Base (book.txt)]
     ↓
[Response] → [TTS Engine] → [Voice Output]
     ↓
[User Profile] → [Firestore] → [Cloud Storage]
```

### Security Layers:

**Application Security:**
- ✅ **API Key Protection:** Environment variables (.env), never hardcoded
- ✅ **Code Obfuscation:** ProGuard/R8 enabled for release builds
- ✅ **HTTPS Enforcement:** All network traffic encrypted
- ✅ **Certificate Pinning:** Planned for Phase 2
- ✅ **Input Validation:** Sanitized user inputs, XSS prevention

**Data Security:**
- ✅ **Firebase Security Rules:** User data accessible only by owner
- ✅ **Encryption at Rest:** Firestore native encryption
- ✅ **Encryption in Transit:** TLS 1.3 for all API communications
- ✅ **Privacy by Design:** Minimal data collection, session-based history
- ✅ **GDPR Compliance:** User consent, data portability, right to deletion

**Authentication Security:**
- ✅ **Multi-Factor Options:** Google OAuth, email verification
- ✅ **Session Management:** Firebase tokens with automatic refresh
- ✅ **Anonymous Access:** Privacy-first approach for guest users
- ✅ **Password Policies:** Firebase-enforced strong password requirements

**Developer Inputs:**
*"Architecture follows microservices principles with clear separation of concerns. Firebase provides enterprise-grade security and scalability, while Flutter ensures consistent cross-platform experience. The RAG system is optimized for quick response times with pre-computed embeddings."* - Technical Team
